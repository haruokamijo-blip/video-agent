# 動画編集の手順

ユーザーは技術者ではない。進み具合は短い日本語で伝え、専門用語は避ける。
コマンドはリポジトリのルートで実行する（Windows では `python3` の代わりに `python`）。

## 1. 解析
```
python3 tools/analyze.py "<動画ファイル>"
```
- 案件名はファイル名から自動で決まる（`--name` で指定可）。以降 `<案件>` と書く。
- 文字起こしに時間がかかる（10分の動画でパソコンにより5〜20分）。始める前にユーザーにそう伝える。

## 2. 自動カット（無音・フィラー）
```
python3 tools/auto_cut.py <案件>
```

## 3. Claude による判断カット
`projects/<案件>/transcript.txt` を全部読み、次を見つけて `timeline.json` の `cuts` に追加する。
- **言い直し・噛み**（type: `retake`）：同じことを言い直していれば、**前の失敗した方**を切る。
- **脱線・冗長**（type: `offtopic`）：本題と関係ない話、同じ説明の繰り返し。
- **自動の保留カット**（`enabled: false` の「あの」「まあ」等）：前後の文を見て、意味のない口癖なら `enabled: true` にする。指示語（「あの本」など）なら false のまま。

追加するカットの形：
```json
{"id": "c001", "start": 12.34, "end": 15.6, "type": "retake", "reason": "「今日は」を言い直している", "enabled": true, "by": "claude"}
```
- 時間は**元動画の秒数**。`transcript.json` の単語の start/end を見て、文の境目に合わせる。
- **確信がない場合は `enabled: false`（保留）**にして、レビューでユーザーに判断してもらう。言い直しは明らかなら true、脱線は原則 false。
- `by: "auto"` のカットの id は変えない（auto_cut の再実行で作り直されるため）。

## 4. テロップ
```
python3 tools/make_telops.py <案件>
```
下書きができたら `timeline.json` の `telops` を全部見直す。
- 文字起こしの誤変換を直す（固有名詞、専門用語、同音異義語）。
- 3でカットした部分の言葉がテロップに残っていたら消す。テロップ全体がカット区間にあれば自動で消える。
- 1行が `telop_max_chars_per_line` 以内に収まるよう `\n` で改行する（最大2行）。意味の切れ目で改行する。
- 文末の「。」は付けない。
- 話の要点・結論・数字など**特に伝えたいところ**は `"style": "emphasis"`（黄色・少し大きい）にする。多用しない（目安：全体の1割以下）。

## 5. プレビューを作る
```
python3 tools/render.py <案件>
```

## 6. ユーザーに報告して確認してもらう
次を短く伝える：
- 長さがどう変わったか（例：12:30 → 9:45）
- 言い直しや脱線で切った箇所の数と、**保留にした箇所**（時間と理由）
- 確認方法：`projects/<案件>/review.html` をブラウザで開く（ダブルクリック）

## 修正依頼への対応
「1:23 のテロップを直して」のような時間は**出来上がり動画の時間**。
`review.html` の一覧（出来上がりの時間が載っている）や、`tools/common.py` の
`keep_segments` / `to_output_time` で元の時間に対応づけてから `timeline.json` を直す。
直したら手順5をやり直し、何を直したかを伝える。

## 完成
ユーザーが OK を出したら：
```
python3 tools/render.py <案件> --final
```
→ `projects/<案件>/final.mp4` ができたことを伝える。
